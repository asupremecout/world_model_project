# World Models 训练历程与问题复盘报告

> 记录从接手项目到当前（两阶段：真实环境训练 / 梦境训练）的完整历程、遇到的每个问题及其根因与解决方式。
> 硬件：单卡 RTX 4090 D（24 GB）、24 物理核 / 32 逻辑线程。所有数字来自实际日志与 `exp*/best.tar`。

---

## 0. 总览

| 阶段 | 目标 | 结果 |
| --- | --- | --- |
| 阶段 0 环境搭建 | 建 py3.9 训练环境 | ✅ 跑通 |
| 阶段 1 真实环境训练 | 复现 VAE+MDRNN+控制器 baseline | ✅ 控制器 704 分（mean 748 / max 907） |
| 阶段 2 梦境训练 | 在「想象中」训练控制器 | ⚠️ 首次失败（对抗利用），正在用专家数据修复 |

核心结论（贯穿全文）：
1. **真实环境训练有效**，因为它直接读游戏真实奖励，绕开了「奖励模型」这个短板。
2. **梦境训练又快又省**（纯 GPU），但完全押在「奖励模型质量」上——奖励模型差，就会被对抗性利用。
3. **奖励模型质量由数据决定**：随机数据 tile 奖励稀疏 → 奖励退化；好驾驶数据 tile 密集 → 才学得会。

## 1. 阶段 0：环境搭建

### 1.1 硬件与网络
- GPU：RTX 4090 D，24 GB，驱动 595.97；CPU 24 核。
- 网络：`pypi.org` 超时（大陆网络），改用**清华 pypi 镜像**；torch cu118 走 `download.pytorch.org`（可达）；conda 已配清华源。

### 1.2 坑 1：`aic` 环境装不了 Box2D
- **现象**：`aic` 是 Python 3.11 + numpy 2.0，缺 gym/Box2D/pyglet/cma/cloudpickle。
- **根因**：`Box2D==2.3.10` / `box2d-py` 都没有 py3.11 的 Windows 轮子（只能源码编译，需 SWIG+MSVC）；`gym 0.21.0`（2021）又与 numpy 2.0 不兼容。
- **解决**：新建专用 `worldmodels` 环境（**Python 3.9**），`Box2D==2.3.10` 有 cp39-win_amd64 轮子，numpy 固定 1.23.5。

### 1.3 坑 2：`gym==0.21.0` 装不上
- **现象**：`error: extras_require must be a dictionary whose values are strings or lists of strings containing valid project/version requirement specifiers`，指向 `opencv-python>=3.`。
- **根因**：gym 0.21.0 的 `setup.py` 里 `extras_require` 含非法的 `opencv-python>=3.`（`3.` 不是合法 PEP440 版本），新版 pip/setuptools 拒绝。
- **解决**：降级 `pip==23.3.2` + `setuptools==59.5.0` + `wheel==0.37.1`，用 `pip install gym==0.21.0 --no-deps --no-build-isolation` 安装。

最终环境：torch 2.5.1+cu118、numpy 1.23.5、gym 0.21.0、Box2D 2.3.10、pyglet 1.5.27、cma 4.5.0。

## 2. 阶段 1：真实环境训练 baseline

### 2.1 坑 3：VAE/MDRNN 训练脚本 Windows 崩溃
- **现象**：`RuntimeError: An attempt has been made to start a new process before the current process has finished its bootstrapping phase.`
- **根因**：`trainvae.py` / `trainmdrnn.py` 的 `DataLoader(num_workers>0)` 在 Windows 用 `spawn` 重新 import 主模块（主模块没有 `if __name__=='__main__'` 保护），触发递归。文档只修了 `traincontroller.py`，这两个脚本同样中招但没被提到。
- **解决**：两文件的 `num_workers` 改为 `0`（数据读取本就在 `load_next_buffer` 里单线程完成，`num_workers` 只影响廉价的 transform，改成 0 几乎无损）。

### 2.2 数据采集
- 策略：Brownian 随机策略，观测 64×64×3。
- 规模：**1,504 局**（16 进程 × 94），磁盘 17.26 GB。
- **实测仅 ~6 分钟**（文档估 40 分钟）——Box2D 无渲染时 ~300+ fps，单局约 3 秒。
- 质量：mean return **-55.3**，每局跑满 1000 帧（随机策略几乎不提前撞死）。

### 2.3 坑 4：MDRNN 的 `to_latent` 崩溃
- **现象**：`RuntimeError: view size is not compatible with input tensor's size and stride (at least one dimension spans across two contiguous subspaces). Use .reshape(...) instead.`
- **根因**：`trainmdrnn.py` 的 `to_latent` 里 `f.upsample(..., mode='bilinear', align_corners=True)` 产出**非连续张量**，后续 VAE 编码器的 `.view()` 无法在非连续张量上工作。
- **解决**：upsample 后加 `.contiguous()`；同时把 `models/vae.py` 的 `.view(...)` 改成 `.reshape(...)`（更健壮，一劳永逸）。

### 2.4 VAE / MDN-RNN 训练成果
- VAE：best epoch 99，**test loss 28.47**（~30 轮起走平，手动停）。
- MDN-RNN（**未开奖励预测**）：best epoch 27，**test loss 1.0008**。

### 2.5 控制器训练（真实环境 CMA-ES）
设置：线性控制器（latent 32 + hidden 256 → 3 动作，共 867 参数），CMA-ES popsize 32、n-samples 8、max-workers 16，在真实 `CarRacing-v0` 上 rollout。

**发现 1：收敛快得反常**——第 3 代就冲到 446 分（target 400 达标自动停）。说明「VAE latent + MDRNN hidden」的世界模型表征让线性控制问题变得非常容易。

**坑 5（认知修正）：速度估计严重错误**——实测每局 **~11~14 秒**（不是外推的 3 秒）。瓶颈不是 Box2D 物理，而是 rollout 每一步的 `图像 transform + VAE/MDRNN/控制器前向 + GPU↔CPU 同步`（每步多次 CPU-GPU sync）。由此推算控制器训练每代 ~3.7 分钟，到 400+ 分需数百代、**10+ 小时**。文档写的「3~7 小时」其实有 10 倍算术错误（按它自己的「40s/局×256局×400代÷16」算出来是 ~71 小时）。

**成果（分段续训）**：
- 第一轮 target 400：446.3 → 自动停。
- 第二轮 target 700：446 → 535.4。
- 第三轮（远程 run3）：535.4 → **704.1**（100 局评估 > 700 → 自动停）。
- 独立复测 8 局：**mean 748 / max 907**（max 已追平论文 906）。

### 2.6 用户发现的两个方法学问题（阶段 1 → 2 的转折）
1. **对比不公平**：控制器用 `--target-return` 早停，无法与「加组件后」的版本在同一预算下公平对比 → 应改为固定代数。
2. **训练域不符**：README 要求「在想象中训练智能体」，但我们走的是 `RolloutGenerator → gym.make('CarRacing-v0')`（真实环境）。仓库自带的梦境环境 `envs/simulated_carracing.py` 并未接入控制器训练。

## 3. 阶段 2：梦境训练

### 3.1 梦境训练原理（见文末附录）

### 3.2 坑 6：梦境需要「奖励预测」，但 MDRNN 没训过
- **现象**：梦境 `SimulatedCarracing.step()` 的奖励 `r` 和终止 `d` 来自 MDRNN 的预测头；而之前的 MDRNN 训练时**没开 `--include_reward`**，奖励头是未训练的随机值 → 梦境给不出学习信号。
- **解决**：重训一个带奖励预测的 MDRNN。

### 3.3 坑 7（关键发现）：奖励预测退化
在随机数据（1504 局）上重训带奖励的 MDRNN 后，专项检验奖励预测质量：

| 指标 | 值 | 判定 |
| --- | --- | --- |
| 实际奖励 | mean -0.073，max 3.55，tile 步占 0.8% | 信号稀疏 |
| MSE(预测,实际) | 0.0883 | 只比「常数 -0.1」的 0.0918 好 3.8% |
| tile 步预测 | 实际 +3.28 → 预测 +0.038 | 幅度被压扁 30 倍 |
| 相关系数 | 0.175 | 弱正相关 |

- **根因**：随机策略踩 tile 太少（0.8% 的步），MDRNN 学不到 tile 奖励，奖励头退化成「几乎永远预测 -0.1」。

### 3.4 坑 8：梦境训练器 bug
- **现象**：脚本引用了 `args.display` 但 parser 里没定义 `--display`，`main()` 在 `Process.start()` 之后才崩 → 留下 16 个孤儿 worker 进程卡死。
- **解决**：补上 `--display` 参数定义。

### 3.5 坑 9（核心失败）：梦境被「对抗性利用」
用弱奖励模型做梦境训练，并迁回真实环境验证：

| 梦境分数（预测回报） | 真实环境 6 局 |
| --- | --- |
| 487 → 775 → 919 → **1132** | mean **-82.4**（等于乱开） |

- **现象**：梦境分数一路涨到 1132（远超奖励预测器在真实数据上的单步上限 0.263 × 1000 = 263），但迁回真实环境只拿 -82 分。
- **根因**：控制器把 latent 推进 MDRNN 的**分布外区域**，奖励头在分布外「幻觉」出高奖励，CMA-ES 钻这个空子。**奖励模型只在训练分布内可信**，这是梦境训练最经典的失败模式。

### 3.6 修复：采集专家数据
- 用 704 控制器在真实环境采 **512 局**，mean return **734**，max **928**（tile 密集，一圈踩 ~300 tile vs 随机的 ~10）。
- 与随机 1504 局混合成 **2016 局**，重训带奖励的 MDRNN（`exp_dream2`）。

### 3.7 坑 10：专家数据导致 MDRNN 训练崩溃
- **现象**：`RuntimeError: shape '[16, 32, 32]' is invalid for input of size 6144`。
- **根因**：`to_latent` 里硬编码 `.view(BSIZE=16, ...)`；随机数据每局都满 1000 帧、每批正好整除 16，而专家数据有提前撞死、长度不一的局 → 最后一批不满 16 → 崩。
- **解决**：`.view(BSIZE, ...)` 改 `.view(-1, ...)`（自动按实际 batch 大小）。

### 3.8 新奖励模型检验（`exp_dream2`）
- 专家数据上相关系数 **0.175 → 0.291**，MSE 比常数基线好 **3.8% → 17.6%**，tile 奖励压缩从 30 倍降到 ~9 倍。
- 学会区分「好驾驶区域（预测均值 +0.18）/ 差驾驶区域（-0.077）」。

### 3.9 梦境训练重试（成功 ✅）
- 梦境分数缓慢爬升（-43 → +462，未爆炸，在奖励模型合理区间内）。
- **迁移真实环境（仅训 34/150 代）**：mean **+52**，max **+131.5**（对比上次弱奖励模型的 **-82**）。
- **结论**：奖励模型质量决定梦境训练成败，这一假设被证实；梦境训练这条路已打通。
- 续训命令（自动从 462 分继续）：
  `python -u traincontroller_dream.py --logdir exp_dream2 --max-generations 150 --pop-size 32 --n-samples 4 --max-workers 16 --time-limit 1000`

## 5. Baseline 协议与结果（改进版的对比锚点）

**协议（改进版必须完全对齐）**：
- 梦境控制器从**随机初始化**单次训练 **200 代**（CMA-ES pop 32 / n-samples 4 / max-workers 16 / time-limit 1000）。
- 迁移到真实环境，跑 **20 条固定赛道（seed=0）**，报 mean±std。

**Baseline 结果**：
- 最佳梦境分数：**479.88**（gen 91）。
- **真实环境 20 赛道：mean -22.4 ± 50.4**（max 110.1，min -129.7）。

**关键发现**：
1. 相比弱奖励模型的 -82（乱开），-22.4 有进步，说明奖励模型修复有效，但迁移仍弱（只比随机 -55 略好）。
2. 瓶颈仍是奖励模型：tile 奖励压缩 ~9 倍、相关性 0.29。
3. gen 34 时 5 局评估 mean 52，但 gen 91 最终 20 局只有 -22.4，暗示**训练越久越过度拟合梦境奖励、迁移反而变差**（model-based RL 经典问题）。

**评估脚本**：`baseline/eval_transfer.py --logdir <dir> --n 20 --seed 0`（改进版用同一条命令、同 seed 对比）。

## 4. 关键结论

1. 真实环境训练 704 分，因为它**直接读真实奖励**，绕开了奖励模型短板。
2. 梦境训练**又快又省**（纯 GPU 前向，无 Box2D 物理/渲染），但**完全押在奖励模型质量上**。
3. 奖励模型质量由**训练数据**决定：随机数据 tile 稀疏 → 奖励退化 → 梦境被对抗利用；好驾驶数据 tile 密集 → 才有救。

## 附录：两种训练的数据来源与原理对比

### A. 现实（真实环境）训练
- **观测**：每步调用真实 `gym.make('CarRacing-v0')`，Box2D 物理 + 渲染产出 64×64×3 图像。
- **奖励**：游戏真实奖励函数（每步 -0.1，踩新 tile +1000/N）。
- **数据来源**：训练时**现场实时采集**——控制器每代要跑 256 局，全部真实跑游戏。
- **速度**：每局 ~11~14 秒（瓶颈是每步的 GPU↔CPU 同步 + 图像 transform）。

### B. 梦境（想象）训练
- **观测**：不需要真实游戏。从随机 latent `z` 出发，控制器给 action，MDRNN 预测下一帧 latent；VAE decoder 可把 latent 解码成图像（训练中通常只需 latent）。
- **奖励**：MDRNN 的**奖励预测头**给出。
- **终止**：MDRNN 的**终止预测头**给出。
- **数据来源**：**自回归「想象」生成**——不采集任何真实数据，纯 GPU 前向逐帧 roll，所以快一个数量级。
- **速度**：每局 ~1 秒。

### C. 但 VAE 和 MDRNN 本身的数据从哪来？
两个阶段共用的上游模型（VAE、MDRNN）都是**用真实环境采集的数据训练的**：
- 随机策略数据：1504 局（brownian 随机策略在真实环境采）。
- 专家数据：512 局（704 控制器在真实环境采）。

所以完整数据流是：

```
真实环境 ──(随机策略)──> 随机数据 1504 局 ─┐
                                          ├─> 训 VAE + MDRNN（含奖励）
真实环境 ──(704控制器)──> 专家数据 512 局 ──┘
                                                    │
        ┌───────────────────────────────────────────┘
        ▼
   VAE + MDRNN（世界模型）
        │
        ├─ 真实训练：控制器直接在真实环境跑，吃真实奖励（不经奖励模型）
        │
        └─ 梦境训练：控制器在 VAE+MDRNN 生成的「想象」里跑，吃 MDRNN 预测的奖励
```

一句话：**梦境训练省的是「控制器训练阶段」的真实环境开销，但「世界模型（VAE/MDRNN）」本身仍要靠真实环境数据来训练。**
